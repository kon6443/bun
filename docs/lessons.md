# Lessons — 누적 실수와 교훈

> **용도**: 사용자 교정·발견된 실수·사후 분석 직후 항목을 **추가(append)** 한다. 세션 시작 시와 대규모 리팩터링 전에 검토한다 (글로벌 `~/.claude/rules/workflow.md` §4 Self-Improvement Loop).
> **경계**: 여기는 **작업 방식(process)의 교훈**이다. 코드 결함의 증상별 진단은 [`playbooks/recurring-issues-playbook.md`](playbooks/recurring-issues-playbook.md), 하지 말 것 목록은 [`../CLAUDE.md`](../CLAUDE.md) Pitfalls.
> **형식**: 항목마다 실패 양상 / 탐지 신호 / 근본 원인 / 예방 규칙 4필드. 새 항목은 **위에 최신순**으로 추가한다.

## 2026-09-23 — `git add` 실패 뒤에도 커밋이 실행돼 내용이 빠진 커밋이 생겼다

- **실패 양상**: 프론트 refactor 커밋에서 `git add <이미 rename 스테이징된 옛 경로> …; git diff --cached --stat; git commit …`을 실행했다. 옛 경로가 pathspec에 안 맞아 `git add` 전체가 실패했는데, `;`로 이어져 있어 커밋이 그대로 진행됐다 → 이름 변경 2건만 담긴(내용 0줄) 커밋이 생겼다.
- **탐지 신호**: 출력 첫 줄 `fatal: pathspec '…' did not match any files`, 그리고 `--stat`이 `0 insertions(+), 0 deletions(-)`.
- **근본 원인**: 스테이징과 커밋을 **실패해도 계속 가는 `;`** 로 이었다. 스테이징 결과를 사람이 확인하기 전에 커밋까지 한 번에 보냈다.
- **예방 규칙**: 스테이징 → 커밋은 `&&`로만 잇거나, **스테이징과 커밋을 별도 호출로 나눠 `--stat`을 확인한 뒤 커밋**한다. push 전이면 `git reset --soft`로 풀고 다시 만든다(이번엔 사용자 승인 후 그렇게 복구 — 원격 영향 없음).

## 2026-09-23 — 글로벌 훅을 프로젝트에 복사하면 사본이 먼저 낡는다 (타 레포 관찰)

- **실패 양상**: nerd-back 레포가 글로벌 `check-secrets.sh`를 `.claude/hooks/`에 복사해 등록했는데, 사본(47줄)에는 글로벌(22줄)이 이후 추가한 시크릿 패턴 6종(`sk_live`·`glpat`·`npm_`·`hf_`·`AGE-SECRET`·`eyJ`)이 **0건**이었다. 글로벌 훅도 같은 이벤트에 등록돼 있어 두 벌이 이중 실행됐다.
- **탐지 신호**: 같은 이름의 스크립트가 `~/.claude/`와 프로젝트 `.claude/hooks/`에 동시에 있다. 두 파일을 grep하면 패턴 수가 다르다.
- **근본 원인**: 복사는 "그 시점의 원본"만 가져온다. 이후 원본만 갱신된다 — 같은 사실을 두 곳에 두면 어긋난다는 2026-08-12 교훈과 같은 구조다.
- **예방 규칙**: 글로벌 훅은 프로젝트에 복사하지 않는다. **예외는 팀 공유가 목적일 때뿐**이고(개인 dotfiles가 없는 팀원도 받아야 할 때), 그때는 두 벌을 비교하는 검사를 함께 둔다 — 이 레포의 `inject-sibling-claudemd.sh`는 형제 레포와 `cmp` 검사(C2-5)로 묶여 있다.

## 2026-09-23 — 권한 deny 규칙을 끝이 `:*`인 모양으로 써서 마이그레이션 차단이 무효였다

- **실패 양상**: 프론트 `.claude/settings.json`에 `Bash(npm run db:migrate:*)`·`Bash(npm * db:migrate:*)`를 넣었는데, headless 세션 탐침에서 `npm run db:migrate:fake-probe`가 **그대로 실행**됐다. 같은 파일의 `Bash(pnpm db:migrate:up*)`는 막혔다. 같은 조사에서 백엔드도 `pnpm run db:migrate:up`·`pnpm --dir . …`이 deny를 빠져나가는 것을 확인했다(`pnpm db:migrate:up*`만 있었다).
- **탐지 신호**: 존재하지 않는 스크립트명(`…-probe`)으로 실행했을 때 권한 거부가 아니라 `Missing script`가 나온다.
- **근본 원인**: ① 끝이 `:*`인 규칙은 옛 접두사 문법으로 해석돼 `db:migrate` 뒤에 `:fake…`가 이어진 명령을 못 잡는다(실측, 해석 규칙 자체는 추정) ② 패턴을 "스크립트명 바로 앞이 `pnpm`"인 한 가지 모양만 썼고, 중간에 `run`·`--dir`이 끼는 형태를 시험하지 않았다. 규칙을 쓰고 **실제로 막히는지 시험하지 않았다**.
- **예방 규칙**: deny 패턴은 끝을 `…up*`처럼 글자 뒤 `*`로 쓰고 `:*`로 끝내지 않는다. 중간 토큰이 끼는 형태(`pnpm run`, `pnpm --dir x`, `npm --prefix x run`, `cd x && …`)를 함께 넣는다. **추가한 deny는 반드시 탐침으로 시험한다** — 실존하지 않는 스크립트명을 쓰면 규칙이 빗나가도 `Missing script`로 끝나 안전하다. 실제 스크립트명으로 시험하지 않는다(`Bash(pnpm:*)`가 allow라 빗나가면 곧 상용 적용).

## 2026-08-12 — 로컬 빌드 성공이 Docker 빌드 성공을 뜻하지 않는다

- **실패 양상**: CI Docker 빌드가 `error TS5058: The specified path does not exist: 'tsconfig.build.json'`으로 실패했다. 로컬 `pnpm build`는 계속 통과하고 있었다. `13d5308`(2026-08-07)에서 `tsconfig.build.json`을 도입하고 `build` 스크립트를 `tsc -p tsconfig.build.json`으로 바꿨는데, **`Dockerfile`의 `COPY` 목록을 함께 갱신하지 않았다**(Dockerfile 최종 변경은 2026-04-06). 5일간 깨진 채였고 `main` 미푸시 상태라 드러나지 않았다.
- **탐지 신호**: 로컬은 통과하는데 CI만 실패. `tsc`가 **설정 파일 자체를 못 찾는** 에러(TS5058)는 타입 오류가 아니라 **입력 파일 집합의 차이**를 가리킨다.
- **근본 원인**: 로컬 빌드의 입력은 **레포 전체**지만 Docker 빌드의 입력은 **`COPY`로 명시한 것뿐**이다. 두 입력 집합이 다르므로 로컬 통과가 컨테이너 통과를 보증하지 않는다. `tsconfig.build.json`은 `extends: "./tsconfig.json"`이라 두 파일이 모두 필요했다.
- **예방 규칙**: 빌드 **진입 설정**(`tsconfig*.json`, `build` 스크립트, 엔트리 경로)을 바꾸면 같은 커밋에서 `Dockerfile`의 `COPY` 목록을 확인한다. 검증은 Docker 없이도 가능하다 — 임시 디렉토리에 `COPY` 목록만 복사하고 `node_modules`를 심볼릭 링크한 뒤 빌드 명령을 돌리면 CI 실패를 그대로 재현할 수 있다. `pnpm ci:all`은 이 종류를 잡지 못한다(레포 전체를 입력으로 쓰므로).

## 2026-08-12 — "좋은 내용"을 CLAUDE.md에 넣는 습관

- **실패 양상**: CLAUDE.md에서 진행 상황·디렉토리 트리를 덜어낸 **직후**에, 공식 문서에서 배운 "좋은 내용" 2개(설정 확장 트리거 표, "이 표는 강제가 아니다" 주의)를 다시 넣어 183줄로 늘렸다. 사용자가 "이게 매 세션 들어가야 하나"라고 지적해 되돌렸다(169줄).
- **탐지 신호**: 추가한 항목이 **Claude의 행동을 바꾸지 않는다**는 점. 유지보수 정책·메커니즘 설명·설정 철학은 읽어도 다음 행동이 같다.
- **근본 원인**: "유용하다"를 "CLAUDE.md에 넣을 이유"로 착각했다. CLAUDE.md는 유용한 지식 저장소가 아니라 **매 세션 행동을 바꾸는 지시만** 담는 곳이다. 공식 기준도 "코드베이스·문서에서 유도 가능한 내용은 잘라내고 함정·근거·기본값과 다른 컨벤션만 남긴다"다.
- **예방 규칙**: CLAUDE.md에 한 줄을 넣기 전에 자문한다 — **"이걸 모르면 내가 틀리게 행동하는가?"** 아니면 넣지 않는다. 길어질수록 정작 중요한 금지 규칙의 준수율이 떨어진다. 공식 문서의 일반 지식은 복사하지 말고 필요할 때 찾아본다.

## 2026-08-12 — 검증 스크립트의 오류를 문서 오류로 착각

- **실패 양상**: 문서 리뷰 중 카운트 대조에서 `code:'SUCCESS' 0건`, `JwtAuthGuard 26건`이 나와 방금 작성한 문서(각 30건, 25건)가 틀렸다고 판단할 뻔했다. 실제로는 문서가 정확했고 측정 명령이 잘못됐다.
- **탐지 신호**: 같은 대상을 앞서 측정한 값과 결과가 어긋남. 그리고 `ugrep: warning: SUCCESS": No such file` 경고가 함께 출력됨.
- **근본 원인**: ① zsh에서 중첩 따옴표(`grep "code: 'SUCCESS'"`)가 깨져 인자가 분리됨 ② `grep -c 'JwtAuthGuard'`가 `OptionalJwtAuthGuard`까지 **부분일치**로 세었다.
- **예방 규칙**: 카운트가 기대와 다르면 **문서를 고치기 전에 측정 명령부터 검산**한다. 부분일치가 가능한 심볼은 경계를 포함한 정확 패턴(`@UseGuards(JwtAuthGuard)`)으로 세고, 경고 출력은 무시하지 않는다.

## 2026-08-12 — 같은 사실을 두 곳에 쓰면 반드시 어긋난다

- **실패 양상**: 동일 지표가 문서마다 달라졌다 — 테스트 커버리지가 `CLAUDE.md`엔 `62.7%`, `tasks-nestjs-improvements.md`엔 `62.64%`. 세션 메모리(`MEMORY.md`)는 4개월 낡아 배포 명령(`docker service update sys_express`)·Redis 호스트(`sys_redis`)가 현행과 달랐고, **레포에서 삭제된 `infra/setup-redis.sh`의 실행을 지시**하고 있었다.
- **탐지 신호**: 두 문서를 나란히 grep했을 때 숫자·서비스명 불일치. 문서가 지시하는 파일이 실제로 없음.
- **근본 원인**: 요약을 별 문서에 **복사**하면 이후 원본만 갱신된다. 특히 세션 메모리는 갱신 트리거가 없어 레포보다 빠르게 낡는다.
- **예방 규칙**: 진행 상황·수치·명령은 **SSOT 한 곳만** 두고 나머지는 링크한다. `CLAUDE.md`에는 진행 상황·완료 이력·커버리지를 쓰지 않는다(문서 경계 표). 메모리에는 레포가 기록하는 사실을 저장하지 않는다.

## 2026-08-12 — 정책 전환 커밋이 문서를 함께 갱신하지 않음

- **실패 양상**: `docs/architecture.md`가 약 4개월간 폐기된 날짜 정책("투과 방식 — 변환 없음", "timezone-naive")을 유지했다. 이 문서는 자동 라우팅 표에서 "구조 파악"의 진입점이라, AI가 **작업 시작 시점부터 틀린 전제**를 갖게 되는 위치였다.
- **탐지 신호**: Entity 컬럼 타입 실측(`timestamp with time zone` 14개)이 문서 서술과 정반대. `CLAUDE.md`·`docs/deploy.md`와도 충돌.
- **근본 원인**: 정책을 전환한 커밋(`2c86d73`, 2026-04-14)이 `CLAUDE.md`는 갱신했지만 **같은 정책을 서술한 다른 문서를 찾지 않았다**. 문서에 최종 확인일이 없어 낡음을 감지할 신호도 없었다.
- **예방 규칙**: 정책을 바꾸는 커밋에서 **바뀐 용어로 `docs/` 전체를 grep**해 서술이 남은 문서를 전부 같은 커밋에서 갱신한다. 새로 만드는 규약 문서는 헤더에 **최종 확인일 + 근거(실측 범위)** 를 적는다.
