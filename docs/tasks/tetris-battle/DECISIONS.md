## D-012 — 운영 Redis maxmemory 128mb → 512mb (2026-10-22)
- **상태**: ✅ 확정 (사용자 지시 — Q6)
- **맥락**: `allkeys-lru`라 한도에 닿으면 TTL과 무관하게 오래된 키부터 지워진다 — 진행 중 대전 방·게임 세션 소실 위험. 사용자 확인: `maxmemory`는 상한일 뿐 미리 잡지 않는다(사용량만큼 할당) — 사실이다.
- **결정**: `infra/docker-stack.yml` `--maxmemory 512mb`, README 운영 옵션 서술 동기화.
- **주의**: ① AOF 재작성(fork) 중에는 쓰기량에 비례해 copy-on-write로 순간 메모리가 늘 수 있다 — 노드 12GB라 512MB 상한에서 여유 ② 상한이 커지면 TTL 없는 키가 덜 지워져 사용량이 서서히 늘 수 있다 → 대전 키는 전부 TTL ③ 반영은 `infra` 스택 재배포(Redis 재시작 → 소켓 순간 끊김, AOF로 데이터 유지). 무중단을 원하면 운영 Redis에서 `CONFIG SET maxmemory 512mb`를 먼저 적용하고 yml은 다음 배포에 반영 — 둘 다 사용자 작업(운영 접근)
- **영향**: 배포 직후 조치 게이트(STATUS). 과거 태스크 문서의 128MB 서술(team-chat-persistence·games·tasks-monitoring)은 당시 기록이라 고치지 않는다.

## D-020 — 경기 중 새로고침은 클라이언트가 즉시 기권(topOut frame 0) (2026-10-22)
- **상태**: ✅ 확정 (메인 판단 — `next-bun-bd` 질의 A안)
- **맥락**: 새로고침 후 토큰 재입장은 서버상 정상 복귀(connected=true)지만 로컬 판이 사라져 lock이 오지 않는다 → 상대가 이 사람뿐이면 경기가 끝나지 않는다.
- **결정**: 재입장 ack의 `rejoin.match`가 PLAYING·alive=true인데 로컬 판이 없으면 프론트가 `topOut{matchId, frame: 0}` 전송. 서버는 topOut frame을 마지막 lock frame 이상으로 보정해 기록(현 구현). 기권자는 RESULT까지 대기 후 rematch로 참가. P5 리플레이 검증에서 리플레이 없는 탈락자는 기권으로 처리.
- **버린 대안**: (B) 서버가 토큰 재입장 시 즉시 KO — 소켓만 끊겼다 붙은 정상 복귀와 구분 불가 (C) 경기 중 자동 재입장 금지 — RESULT 전까지 방에 못 들어옴
