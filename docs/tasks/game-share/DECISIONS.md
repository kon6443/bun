## D-002 — 모바일 기본 공유 시트(Web Share API) (2026-10-21)
- **상태**: ✅ 확정 (사용자 답변 — "A + B 둘 다"의 B)
- **결정(안)**: 공유 메뉴에 "더보기"(`navigator.share`)를 둔다 — 지원 기기(대부분 모바일)에서 OS 공유 시트가 열려 카톡·인스타 DM·문자 등 아무 앱으로 보낼 수 있다. 미지원(데스크톱 일부)이면 버튼을 숨긴다.
- **근거**: SDK·키 없이 동작하고, 카톡 SDK가 막힌 환경(인앱 브라우저 등)의 대체 경로가 된다.

## D-003 — 기록별 링크 미리보기 (OG 이미지·제목) (2026-10-21)
- **상태**: ✅ 확정 (사용자 답변 — 1차 범위 ②)
- **결정(안)**: 리플레이 링크의 미리보기에 "○○님의 테트리스 12,340점 · 42줄 · 레벨 5" 제목과 기록 카드 이미지(Next `opengraph-image`, 서버에서 기록 요약 조회)를 싣는다. 카카오 공유 카드도 같은 이미지·문구를 쓴다.
- **근거**: 공유의 목적이 유입이라 링크만 보내면 클릭률이 낮다. 미리보기 카드가 "무엇을 보러 가는지"를 보여준다.
- **영향**: 백엔드에 가벼운 기록 요약 조회(리플레이 입력 없이 이름·점수·detail)가 있으면 좋다 — 현재 리플레이 API는 입력 기록 전체(수 KB~수십 KB)를 준다. 리플레이 페이지는 현재 noindex — 미리보기(OG)는 noindex여도 카카오·메신저 스크래퍼가 읽는다(검색 노출과 별개).

## D-005 — 도전장 링크 (2026-10-21)

## D-006 — 카카오톡 공유는 SDK 버튼(A) + 기본 공유 시트(B) + 링크 복사 (2026-10-21)

- **결정**: 공유 메뉴 = [카카오톡](카카오 JS SDK `Kakao.Share.sendDefault` feed 카드) · [링크 복사] · [더보기](Web Share — 지원 기기만). 카카오 SDK는 리플레이 화면에서만 지연 로드하고, 키가 없거나 로드 실패면 카카오톡 버튼을 숨긴다(B·복사는 그대로 동작).
- **필요(사용자 작업)**: 카카오 로그인 앱의 **JavaScript 키**(로그인은 REST 키 `KAKAO_CLIENT_ID` — `Kakao.init`에 쓸 수 없음) + [플랫폼 > Web] 사이트 도메인 등록(운영·`http://localhost:3000`). 키 env `NEXT_PUBLIC_KAKAO_JS_KEY` — 빌드 때 번들에 들어가므로 Docker 빌드 인자로 주입(BUILD_SHA 방식). JS 키는 공개 키 — 보호는 도메인 등록으로
- **근거**: WORKLOG 프론트 조사 절(SDK·키 없음, `src/lib/auth.ts:13-14`)

## D-008 — 기록 요약 조회 API + 프론트 캐시 (2026-10-21)
- **상태**: ✅ 확정 (메인 판단 — 프론트 조사 질의 근거)
- **결정**: `GET /games/:gameType/scores/:scoreId` 공개 요약(랭킹 항목과 같은 필드 + 전체 순위, 숨김·없음 404) 신설. 리플레이 API는 입력 기록까지 실어 OG 용도로 무겁다. 미리보기(generateMetadata·OG 이미지)는 Next 서버에서 이 API를 부르며 기록별 캐시(`revalidate` 10분)를 둔다.
- **스로틀**: 전역 스로틀(초당 5·분당 60) 유지 — Next 서버 발 호출은 모든 사용자가 같은 IP 키지만 기록별 캐시로 기록당 10분에 1회만 백엔드에 닿는다. 면제 키는 두지 않는다(새 우회 경로를 만들지 않음).
- **조회 실패 시**: 미리보기는 일반 테트리스 카드로 폴백(Next 404 금지 — 크롤러 캐시에 404가 남지 않게), 재생기는 기존 "기록을 찾을 수 없어요".

## D-009 — 미리보기 이미지 한글: 런타임 subset 폰트 + 실패 시 영문 카드, 번들은 운영 확인 후 (2026-10-21)
- **상태**: ✅ 확정 (메인 판단 — 프론트 결정 요청)
- **맥락**: next/og 기본 폰트는 라틴 전용. DESIGN §3은 "깨지면 폰트 번들"이었으나 프론트는 카드 글자만 Google Fonts `text=` subset으로 받고(하루 캐시·3초 예산) 실패 시 ASCII 카드(한글 이름 숨김)로 렌더한다 — 이미지는 깨지지 않는다.
- **결정**: 그대로 둔다(수 MB 한글 폰트 바이너리를 레포에 넣지 않는다). 운영 컨테이너의 외부 접속 여부는 `docker exec`(운영 접근 — 사용자 확인 필요) 대신 **배포 후 운영 미리보기 이미지(`/games/tetris/replays/{id}/og`)를 열어 한글 이름이 보이는지**로 확인하고, 영문 카드면 그때 폰트 번들을 결정한다.
- **영향**: DESIGN §3 "한글 폰트" 서술 대체. 배포 직후 조치 항목에 추가.
