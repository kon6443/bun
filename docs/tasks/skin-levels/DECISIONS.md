## D-001 — 새 스킨 2종·레벨 5단계·포인트 소비 강화·로그인 기록 소급 (2026-10-27, 사용자)
- **맥락**: 사용자 — "투명 스킨이랑 초콜릿 스킨 추가", "모든 스킨에 레벨, 점점 화려해지게", "게임 점수로 강화, 스킨별로 레벨과 요구 점수". 선택지(장착 숙련도 / 포인트 소비 / 계정 누적 해금) 중 **포인트 소비 강화** 선택
- **결정**:
  - 새 아이템 `clear`(투명)·`chocolate`(초콜릿) — 4슬롯 모두, 무료(`free`)
  - **모든 아이템에 레벨 Lv1~Lv5** (default 포함). 레벨이 오를수록 화려해진다(시각 표현은 프론트). Lv1 = 지금 모습
  - **강화 = 포인트 소비**: 테트리스 점수가 계정 포인트로 쌓이고, 사용자가 고른 아이템(슬롯 × 아이템)을 한 단계씩 강화한다
  - 레벨 누적 요구 점수 기본안: Lv2 10만 · Lv3 30만 · Lv4 100만 · Lv5 300만 → **단계별 비용 10만·20만·70만·200만**. 값은 서버 카탈로그 상수(나중에 조정)
  - **소급**: 이미 쌓인 기록도 포인트에 반영 — USER_ID가 있는 기록(로그인 기록)만 가능(비로그인 기록은 주인이 없다. 사용자 확인)

## D-002 — 포인트·레벨 설계 (2026-10-27, 메인 — D-001에서 파생)
- **포인트 = 적립(파생) + 원장(소비·이후 보상)**
  - 적립은 따로 저장하지 않는다: `SUM(GAME_SCORES.SCORE)` (TETRIS · USER_ID = 본인 · IS_HIDDEN = 0). 점수는 서버가 리플레이로 검증한 값이라 그대로 쓴다(1점 = 1P)
    - 소급이 자동이다 — 백필 마이그레이션이 없어 "백필 실행 ~ 배포" 사이 기록이 빠지는 틈이 없다
    - 숨김 처리된 기록은 포인트에서도 빠진다(잔액이 음수가 되면 0으로 표시하고 강화만 막는다)
  - 원장 `USER_POINT_LEDGER`: 소비(강화, 음수)를 남긴다. 이후 출석·업적 보상(양수)도 같은 표에 REASON으로 더한다. `UNIQUE (USER_ID, REASON, REF_KEY)` — 같은 강화(슬롯·아이템·레벨)는 한 번만 차감
  - 잔액 = 적립 + 원장 합계
- **레벨 저장** `USER_SKIN_LEVELS` (USER_ID, SLOT, SKIN_ID, LEVEL, UPDATED_AT; PK USER_ID+SLOT+SKIN_ID). 행 없음 = Lv1
- **강화 동시성**: 한 트랜잭션에서 `USERS` 행 `FOR UPDATE`(사용자별 직렬화) → 잔액·현재 레벨 확인 → 레벨 저장 + 원장 차감. 다른 아이템을 동시에 강화해도 잔액을 넘겨 쓰지 않는다
- **대상 게임**: 테트리스 싱글(일반·데일리·도전장) 점수만. 대전은 점수가 없어 1단계 제외(승리 보상은 후속), 디펜스는 점수 척도가 달라 제외
- **표시 규칙**: 장착한 아이템은 **현재 레벨**로 그린다. 보드 슬롯은 보드 주인의 레벨(대전 방·리플레이), 화면 배경은 보는 사람 자신의 레벨. 리플레이는 그 판 시작 때의 레벨로 고정(tetris-skins D-006·D-007과 같은 규칙)
- **API 계약 (추가만)**:
  - 보드 스킨 객체(`RoomPlayer.skins`·싱글 리플레이 `skins`·대전 경기 조회 `players[].skins`)에 `levels: { block, effect, board }` 추가. 레벨 이전 기록은 모두 1
  - `GET /users/me/skins`: 카탈로그 항목에 `level`·`nextCost`(만렙이면 null), 최상위 `points: { balance, earned, spent }`, `equippedLevels`
  - `GET /games/tetris/skins`(도감): 항목에 `level`(게스트 1)·`maxLevel`, 최상위 `levelCosts`, 로그인이면 `points`
  - 신규 `POST /users/me/skins/upgrade` `{ slot, skinId, level }`(목표 레벨). 이미 그 레벨 이상이면 차감 없이 200(중복 클릭 안전). 에러: 모르는 아이템 422 `USER_SKIN_UNKNOWN` · 미보유 403 `USER_SKIN_NOT_OWNED` · 한 단계 건너뜀 409 `USER_SKIN_LEVEL_MISMATCH` · 포인트 부족 409 `USER_POINTS_INSUFFICIENT` · 범위 밖 레벨 422(ValidationPipe)
  - 싱글 제출 응답에 `points: { earned, balance } | null`(로그인 테트리스만) — 결과 화면 "+N P"

## D-003 — 투명·초콜릿은 한 색 계열, 레벨 차이를 더 크게 · 실강화 검증 허용 (2026-10-27, 사용자) — supersedes 프론트 설계안의 "초콜릿 7종 맛 색"
- **맥락**: 사용자 — "투명이랑 초콜릿은 게임보이 스킨처럼 한 가지 색으로. 투명은 진짜 유리처럼, 초콜릿은 초콜릿 갈색으로", "강화할수록 조금 더 티 나게", "강화해도 돼, 내 계정으로 진행"
- **결정**:
  - `clear`: 무색 유리 한 계열 — 몸통은 거의 투명, 블록 구분은 밝은 외곽선·반사광·명도 차로. 판 가독성 유지
  - `chocolate`: 갈색 한 계열 — 블록 종류는 같은 갈색의 명도 단계(게임보이처럼)와 초콜릿 바 분할선 질감으로 구분
  - 레벨 레이어는 단계마다 한눈에 구분되게 대비를 키운다(프론트 설계, 375 실측으로 판정)
  - 브라우저 검증에서 사용자 계정(USER_ID 1)으로 실제 강화 허용 — 운영 DB에 원장·레벨이 남는다

## D-004 — 포인트를 원장 하나로: 적립도 한 줄씩 기록 + 메모 (2026-10-27, 사용자) — supersedes D-002의 "적립은 GAME_SCORES 합계로 파생"
- **맥락**: 사용자 — "포인트 발급받을 때마다 어디서 나온지 최소한의 추적이 가능하도록 메모 같은 것으로 누적 기록, 합산해서 현재 포인트를 추적하는 구조". 메인 권장안(원장 일원화) 선택
- **결정**:
  - `USER_POINT_LEDGER` 하나가 포인트의 SSOT — 적립(+)·소비(−)·이후 보상 모두 한 줄씩. 잔액 = 원장 합계(0 미만이면 0으로 표시)
  - 컬럼 `MEMO` 추가(사람이 읽는 설명, 예: "테트리스 기록 #41 · default 보드 · 12,340점", "블록 chocolate Lv2 강화")
  - 적립: 로그인 테트리스 기록 저장과 **같은 트랜잭션**에서 `+점수 · TETRIS_SCORE · REF_KEY=SCORE_ID`. 0점 판은 적립 없음(AMOUNT <> 0). 유니크 (USER_ID, REASON, REF_KEY)가 같은 판 이중 적립을 막는다
  - 소급: 마이그레이션이 과거 로그인 TETRIS 기록(숨김 제외)을 같은 형식으로 원장에 넣는다(NOT EXISTS — 다시 돌려도 중복 없음)
  - 숨김 처리: 더 이상 자동으로 빠지지 않는다 — 숨길 때 차감(−) 기록을 넣는 것은 후속
- **배포 순서**: 마이그레이션(MEMO·소급) → 배포. 그 사이 옛 코드가 저장한 로그인 기록은 원장에 빠질 수 있다 → 배포 직후 `db:select`로 누락 0건 확인, 있으면 소급 SQL을 사용자가 1회 실행

## D-005 — 포인트 내역 API (2026-10-27, 사용자 요청 "포인트 히스토리 페이지" → 메인 설계, 프론트 계약 요청 반영)
- `GET /users/me/points/history?beforeId=&limit=&type=` (로그인 전용) → `{ points, items[{ id, amount, reason, refKey, meta, memo, createdAt }], nextCursor }`
  - 정렬: CRTD_AT 내림차순 → LEDGER_ID 내림차순(소급 줄은 id와 시각이 어긋나서). keyset: beforeId 줄의 (시각, id) 다음부터. 없거나 남의 id면 빈 페이지
  - `type=earn|spend` 서버 필터(커서 페이지라 클라이언트 필터 불가) · limit 기본 20·최대 50
  - `meta`: TETRIS_SCORE `{ scoreId }` · SKIN_UPGRADE `{ slot, skinId, level }` · 그 밖 null — 화면 문구는 프론트, memo는 폴백
  - 기각: `replayAvailable` — 리플레이 공개 규칙(숨김·당일 데일리)은 games 모듈 소관이라 users 모듈이 알 필요 없음. 프론트는 리플레이 API 404를 처리
- 페이지 위치·화면은 프론트 제안(`/games/tetris/points`) — 사용자 확인 대상
