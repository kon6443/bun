  - 서버는 자리에 `tabId`를 저장한다
- **결정 — 자리 찾기**(`commitJoin`, CAS 안에서 판정):
  1. 토큰이 일치하는 자리
  2. 없으면, 로그인 유저(`who.userId !== null`)는 같은 userId의 자리
  3. 없으면 이 소켓의 자리(B-3, 토큰 재발급)
  4. 없으면 새 자리
- **결정 — 넘겨받기 거부**: 1·2로 찾은 자리가 아래를 모두 만족하면 `SEAT_IN_USE`로 거부한다
  - 방이 `PLAYING`이다
  - 그 자리가 매치 참가자다
  - `connected=true`다
  - 다른 소켓이 대표하고 있다
  - 요청의 `tabId`가 자리의 `tabId`와 다르다(없음 포함)
- **결정 — 넘겨받기 성공**:
  - socketId·연결 상태와 함께 `tabId`를 요청 값으로 갱신한다(프론트 조건 1)

  - 자리 이름은 기존 값을 유지한다
  - 이전 소켓이 있으면 채널에서 빼고 `sessionReplaced { code }`를 보낸다
- **결정 — 사전 검증**: 1·2로 자리를 찾으면 정원·상태·비밀번호 검사를 생략한다(지금의 isSameSocket과 같은 취급). CAS 안에서 그 자리가 사라졌으면 기존 규칙대로 ROOM_BUSY
- **결정 — 비교 조건**: tabId는 1·2가 성립할 때만 비교한다. tabId만으로는 아무것도 허용하지 않는다(프론트 조건 2)
- **근거**: 프론트 T-1 평가. resume 플래그는 "대기실에서 넘겨준 기기의 반쯤 열린 소켓이 경기 중 재연결로 되빼앗는" 실패 경우가 있다. fetchSockets 재확인은 반쯤 열린 소켓을 못 잡는다
- **버린 대안**: `resume: true` 플래그 · fetchSockets 생존 재확인
- **영향**: API 계약 추가(요청 `tabId?`, 에러코드 `SEAT_IN_USE`, 서버 이벤트 `sessionReplaced`) — 기존 클라이언트(tabId 없음)도 동작한다. 단, 경기 중 반쯤 열린 소켓 재연결은 SEAT_IN_USE가 되므로 백·프 동시 배포

## D-009 — 유예 만료·저장 마감의 "깨우기" 타이머 (BE-06·FE 방장 이양 의견) (2026-10-23)

  - **결과**: 감지는 최악 약 15초(TTL 10 + 게이트 5)
  - **UI**(프론트): 온라인은 초록 점, 오프라인은 회색 점 + "오프라인" 문구(+ 선택: 유예 카운트다운)로 표시한다. 대기실과 대전 화면의 상대 미니보드에 모두 적용한다. 서버 계약 추가는 없다(`connected`와 ROOM_STATE를 그대로 쓴다)

- **버린 대안**: socket.io pingInterval·pingTimeout 단축(다른 namespace 영향) · 생존 확인 프로브 주기 단축(fetchSockets 비용, 반쯤 열린 소켓은 채널에 남아 있어 못 잡음)
- **하위 호환**: `heartbeat` 선언이 없는 클라이언트(배포 중 열려 있던 옛 탭)는 하트비트 판정에서 뺀다

## D-011 — 강퇴: 대기실·결과 화면에서만, 재입장 허용 (2026-10-23)
- **결정**(사용자 선택):
  - **이벤트**: 새 클라이언트 이벤트 `KICK_PLAYER { code, playerId }`
  - **조건**: 방장만, 방 상태 WAITING·RESULT, 대상은 방장 본인이 아닌 참가자. 위반 시 에러코드는 NOT_HOST · MATCH_ALREADY_STARTED · `PLAYER_NOT_FOUND`(신규)
  - **처리**: 대상 자리를 뺀다. 대상 소켓은 채널에서 빼고 `kicked { code }`를 보낸다. 방에는 ROOM_STATE와 로비를 방송한다
  - **재입장**: 막지 않는다. 대상의 토큰은 자리와 함께 무효가 되어, 다시 들어오면 새 자리가 된다
  - **빈도 제한**: 방·방장 단위 10회/10초
- **버린 대안**: 재입장 차단(게스트는 다른 브라우저로 우회 가능 — 사용자 선택에서 제외) · 경기 중 강퇴
- **영향**: API 계약 추가(클라이언트 이벤트 `kickPlayer`, 서버 이벤트 `kicked`, 에러코드 `PLAYER_NOT_FOUND`)

## D-012 — 하트비트를 "서버 신호에 응답"으로 (supersedes D-010의 클라이언트 3초 타이머 부분) (2026-10-23)
- **맥락**: D-010은 클라이언트가 3초 타이머로 하트비트를 보낸다고 정했다. 그런데 크롬은 5분 넘게 숨겨진 탭의 연쇄 타이머를 1분에 1번으로 줄인다(intensive throttling). 그러면 살아 있는 백그라운드 탭이 오프라인으로 판정되고 자리가 정리되는 회귀가 생긴다. 반면 소켓 메시지 이벤트 핸들러는 이 제한을 받지 않는다
- **결정**:
  - 서버가 각 레플리카에서 **자기 소켓에만**(`server.local`) 4초마다 `presencePing`(페이로드 없음)을 보낸다
  - 클라이언트는 방 안에 있으면 받는 즉시 `heartbeat { code }`로 응답한다. 클라이언트 타이머는 쓰지 않는다
  - TTL 10초, 판정 게이트 5초, 소켓 끊기는 D-010과 같다
  - 서버 타이머는 공유 상태를 두지 않고 로컬 소켓에만 신호를 보낸다 → 중복 실행 문제가 없다(D-009와 같은 판단). `onModuleDestroy`에서 정리한다
- **영향**: 계약에 서버 이벤트 `presencePing`을 추가한다. `heartbeat?: true` 선언과 `heartbeat` 이벤트는 그대로 둔다

## D-013 — 탈락 후 관전·기록 재생에서 보드 확대 보기 (2026-10-23)
- **맥락**: 사용자 추가 요청 원문: "멀티에서 죽거나, 다시보기 할 때 특정 유저 화면 누르면 그 화면이 커지고 다시 돌아갈수있고 기능도 추가해줘."
- **결정**:
  - 적용 화면 ①: 대전 중 내가 탈락한 뒤의 화면. 상대 미니보드를 누르면 그 보드를 크게 보고, 돌아가기로 원래 배치에 복귀한다
  - 적용 화면 ②: 경기 기록 재생(4분할) 화면. 같은 동작이다. 재생 진행과 컨트롤은 그대로 유지한다
  - 범위: 프론트 전용 UI. 서버 계약 변경은 없다(관전 데이터는 기존 opponentUpdate·재생 트랙을 쓴다)
  - 접근성: 보드는 버튼 역할(키보드 Enter·Space, aria-label "○○ 화면 크게 보기"). 돌아가기는 버튼 + Esc, 포커스를 되돌린다
  - 생존 중(내 판 진행 중)에는 확대하지 않는다 — 조작 화면을 가리지 않게. 현재 동작 유지
- **영향**: 프론트 P1 묶음 뒤 별도 묶음(FE-28)

## D-015 — 리뷰로 바뀐 세부 (supersedes D-007의 "userId 경로 매치 해시 갱신", D-010의 하트비트 키 단위) (2026-10-23)
- **userId 넘겨받기는 방 자리 토큰만 새로 준다**(매치에 복사한 토큰 해시는 그대로). 그 경기의 입력 기록은 원래 탭에만 있어 리플레이는 원래 탭이 원래 토큰으로 낸다. 바꾸면 결과 화면에서 다른 기기로 들어오는 순간 원래 탭의 제출이 403 → MISSING(리뷰 R1). 매치 해시 갱신(L7)은 같은 소켓 재발급(B-3)에만 남는다
- **하트비트 키는 소켓 단위** `tetris-battle:hb:{code}:{socketId}` — 자리를 넘겨준 옛 탭의 답이 넘겨받은 소켓의 생존으로 세지지 않게(리뷰 R1)
- **하트비트로 끊을 때는 이 namespace만**(`disconnectSockets(false)`) — 같은 연결의 다른 namespace를 닫지 않게. 클라이언트는 "io server disconnect"에서 직접 재연결(프론트 반영)
- **검증 진행 중 겹친 제출은 503**(409 아님) — 프론트 replaySubmit이 503을 재시도한다
- **수용(고치지 않음)**:
  - (리뷰 R2 #3) 결과 화면에서 기기 B가 userId로 넘겨받은 뒤, 같은 B 소켓이 토큰 없이 다시 join하면 같은 소켓 갈래가 매치 해시를 B 토큰으로 바꿔 원래 탭 A의 제출이 403이 될 수 있다. 넘겨받기 + 같은 소켓의 토큰 없는 재입장이 겹쳐야 하고, 프론트는 토큰을 메모리·저장소에 들고 있어 토큰 없이 다시 보내지 않는다 → 빈도가 매우 낮아 수용한다
  - (리뷰 R2 #7) 가비지 상한(대상당 3600건)에 걸린 대상에 공격 커서가 머물러 그 공격자의 공격이 다른 생존자에게도 가지 않는다. 3600건은 사실상 도달하지 않는 값이라 수용한다(BE-14의 의도: 상한 때 커서가 건너뛰어 공격이 조용히 사라지지 않게)

## D-016 — 경기 중 채팅: 탈락자는 입력, 생존자는 읽기만 (2026-10-23)
- **맥락**: 사용자 추가 요청 원문 "테트리스 죽으면 채팅 기능도 넣어줘. 살아있을떄도 게임플레이에 방해 안되면 넣어도 될듯."
- **결정**(사용자 선택):

  - **프론트**: 탈락·관전 중에는 채팅 입력창과 목록을 보여 준다. 생존자에게는 판을 가리지 않는 작은 자막(최근 1~2줄, 몇 초 뒤 사라짐)만 보여 준다. 생존자의 입력은 기존 이모트 버튼뿐이다
- **영향**: 계약 동작 변경 — `chat`이 PLAYING에서 탈락자에게 허용된다(에러코드·이벤트 추가 없음)
