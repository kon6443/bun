## D-002 — 수정 계획 P1~P6 전부 진행, 하이라이트 마커 포함 (2026-10-23)
- **맥락**: 전수조사(백 BT·BD, 프 FE) 후 계획안 승인 요청. Q1(하이라이트 마커)은 원래 비목표(신기능)
- **결정**: STATUS 계획안 P1 battle → P2 submit → P3 defense → (리뷰) → P4 replay(하이라이트 마커 포함) → P5 ux → P6 refactor → (리뷰). 하이라이트 1차는 프론트 단독(API·DB·엔진 무변경), 서버 저장은 2차 후보
- **근거**: 사용자 선택 "P1~P6 전부 진행". 프론트 Q6 답 — 엔진 `lastLock`·`sentLog`·`EVENT`가 이미 공개돼 재시뮬만으로 계산 가능, 디펜스 `prepareReplay`에 마커 레일 패턴 존재
- **버린 대안**: P1~P3 먼저 배포 · 하이라이트 제외
- **영향**: 비목표에서 "리플레이 하이라이트 1차"를 뺀다

## D-003 — BD-05: 보드별 동일 리플레이 중복 등록 차단 (2026-10-23)
- **맥락**: 주간 보드는 전원 같은 seed라 유효 리플레이 1개를 새 세션으로 반복 제출해 랭킹 도배 가능. games D-004의 "1인 최고점 vs 모든 기록"은 미확정
- **결정**: "모든 기록 등록" 정책은 유지하고, 같은 보드에 같은 리플레이(입력 해시)만 막는다 — 리플레이 해시 컬럼 + `(GAME_TYPE, BOARD_KEY, REPLAY_HASH)` 유니크, 위반 시 신규 에러코드(additive). P2에 포함
- **근거**: 사용자 선택 "동일 리플레이 중복 차단"
- **버린 대안**: 1인 1기록(랭킹 의미 변경 폭 큼) · 현행 유지
- **영향**: Entity + 마이그레이션 세트(파일 작성은 AI, 실행은 담당자 — 머지 전 차단 게이트) · API 계약 추가 → 프론트 에러 문구 대응 · 기존 행은 해시 NULL 허용
