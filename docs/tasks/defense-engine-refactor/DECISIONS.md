# 디펜스 엔진 리팩토링 — 결정 로그

> 새 결정은 맨 아래에 추가한다. 뒤집힐 때는 새 항목에 `supersedes D-00N`.

## D-001 — 디펜스 엔진만, 0단계(측정·안전망) 먼저 (2026-10-24)
- **맥락**: 사용자 "엔진 리팩토링 가능한가, 성능 개선되나, 장단점 — 할 때는 진짜 문제없이". 메인 분석: 테트리스는 이미 가볍고(서버 최악 약 78ms) 이득이 작음, 디펜스는 핫패스 객체 할당(BD-09)·번들(FE-16)·모바일 복원(데스크톱도 1.5~2.8초)에 여지. 엔진은 백·프 바이트 동일·서버 리플레이 재검증이라 결과가 1비트라도 바뀌면 기존 랭킹이 깨진다
- **결정**(사용자 "디펜스만 측정이랑 안전망부터 진행"): 0단계 = 기준선 측정 + 차등 테스트 안전망(결정적 코퍼스 중간·최종 해시, 운영 리플레이 회귀), 엔진 무변경. 결과를 보고 1단계(결과 동일 리팩토링, ENGINE_VERSION 유지) 진행 여부를 사용자가 정한다
- **영향**: 백·프 테스트·도구·픽스처 추가만

## D-002 — 운영 리플레이 회귀 픽스처 대신 생성 코퍼스를 주 안전망으로 (2026-10-24)
- **맥락**: 수용 기준에 "운영 랭킹 리플레이 전부 재검증·익명 픽스처"를 넣었으나, 운영 DB 디펜스 기록이 3건뿐(그중 테스트 기록 2건)
- **결정**: 운영 3건은 재검증만 하고(가능한 범위 — 진행 중인 주간은 공개 API로 못 받음), 회귀 픽스처는 결정적 생성 코퍼스(수천 판, 중간·최종 해시)로 대신한다. 1단계 배포 직전에 그 시점 운영 기록 전체를 다시 재검증한다
- **근거**: `pnpm db:select` — `SELECT BOARD_KEY, COUNT(*) … WHERE GAME_TYPE='DEFENSE' GROUP BY BOARD_KEY` → endless-s1 1 · weekly-2026-w43 2

## D-003 — 1단계 진행: 결과 동일 리팩토링, 측정 순위대로 한 단계씩 (2026-10-24)
- **맥락**: 0단계 완료 보고(기준선·안전망·후보). 사용자 "계속 진행해" — 권장안(1단계 진행, statValue 캐시부터)과 0단계 브랜치는 1단계와 함께 머지
- **결정**:
  - 순서: R1 `statValue` 캐시(CPU self 38%) → R2 핫패스 임시 객체 재사용(재생 1회 약 170MB 할당) → R3 그 밖 핫스팟(attack·step·slotCover·updateAndMoveEnemies) → R4 모듈 분리(번들, 분석 후 판단). `getStateHash` 변경은 하지 않는다(픽스처 재생성 필요 — 필요해지면 별도 결정)
  - 단계마다 게이트: 프론트 이식용 72판 + 전체 4,000판 + 골든 통과 → plain Node 기준선과 같은 조건으로 전후 측정(이득 없으면 그 변경은 넣지 않음) → 메인이 백엔드 사본 동기화(엔진 파일 바이트 동일 + 매니페스트 갱신) → 백엔드 코퍼스 72판·골든·매니페스트 spec·ci:core
  - ENGINE_VERSION 유지(결과 동일이 안전망으로 증명되므로). 동일성을 증명하지 못하는 변경은 제외
  - 리뷰는 R1~R4 끝에 1번(두 리뷰어 확정 0), 배포 직전 그 시점 운영 디펜스 기록 전체 재검증(D-002)
- **영향**: 엔진 원본(프론트 `defense/engine/**`)·백엔드 사본(`src/modules/games/defense-engine/**`)·매니페스트(백·프)

## D-004 — R3 건너뜀, 표적 탐색 공간 색인은 후속으로 (2026-10-24)
- **맥락**: R2 뒤 CPU 프로파일(inspector 100µs, 코퍼스 #2093·#3636·#680 × 6) — 약 30%가 "타워 × 적" 전수 거리 스캔(selectTarget 10.5 · distanceSquared 8.6 · canHit 6.7 · anyInRange 3.9, `--no-turbo-inlining` 기준). 순수 오버헤드 최대 후보(runUltimate 타이머 조기 반환)를 실측한 결과 −0.9~−3.6%로 측정 잡음 수준
- **결정**: R3는 커밋 없이 건너뛰고 R4(번들 분석)로 간다. 남은 30%를 줄이려면 공간 색인·표적 캐시가 필요한데, 동률 규칙(진행 거리 → 생성 순)을 모두 보존해야 하는 구조 변경이라 1단계 범위(대형 분해 제외) 밖 — 후속 후보로 둔다. 타워별 파생값 캐시는 업그레이드·증강 때 무효화가 필요한 상태성 캐시라 위험에 비해 이득(1~4%)이 작아 제외
- **근거**: D-003 게이트 "이득 없으면 그 변경은 넣지 않음" · 프론트 보고(cb8f2b7 대비 3회 교대, 부하 2.6~5.6)
- **영향**: 없음(코드 변경 없음)
