## 0. 핵심 결론 (요약)

1. **웨이브는 "예산(threat budget) × 역할 패턴"으로 만든다.** 웨이브 n의 위협 예산 `B(n)`을 다항식(2차)으로 키우고, 5웨이브 주기 톱니(sawtooth) 배율로 러시·휴식·보스 리듬을 준다. 적 수는 예산 ÷ 적 단가로 정해진다. (제안 — 구조는 [S10][S11][S12] 차용)
2. **HP 성장과 수량 성장을 분리한다.** 적 단가가 HP 배율을 따라 오르게 하면, 같은 예산 안에서 "수 → HP" 비중이 자연히 이동한다(초반 떼, 후반 탱커).
3. **경제는 위협에 비례하게 주고, 누적 자원의 n³ 성장을 감쇠시킨다.** 예산은 n² 성장인데 누적 골드는 n³ 성장이라 후반이 쉬워지는 구조적 문제가 있다. BTD6가 51·61·86·101·121라운드에 킬 보상을 깎는 이유와 같다 [S2][S3]. 우리는 킬 골드 비율 감쇠 + 상위 업그레이드의 골드당 DPS 체감으로 막는다. (제안)
4. **난이도 모드는 "적 HP 배율 + 타워 비용 배율" 두 축만 쓴다.** Kingdom Rush는 적 HP ×0.8/×1.0/×1.2(내림)[S5], BTD6는 비용 ×0.85/×1.0/×1.08/×1.2 [S4]. 속도·보상은 모드 간 동일하게 두는 편이 랭킹 비교와 밸런싱이 쉽다.
5. **무한 모드는 BTD6식 "구간별 가산 램프"** (2%→5%→15%→35% / 웨이브, 가산·비복리)[S1]를 정수 permille로 그대로 쓸 수 있다.
6. **숨은 DDA는 랭킹 게임에서 쓰지 않는다.** 결과 비교 가능성이 깨진다. 대신 명시적 모드·별점·선택형 보조(랭킹 미등록)를 쓴다. (근거: [S13][S14] + 우리 랭킹 요구사항)
7. **메타 진행(영구 강화)은 랭킹 모드에서 끈다.** BTD6 CHIMPS는 Monkey Knowledge·파워·판매·추가 수입을 끄고[S8], Slay the Spire 데일리는 같은 시드·고정 조건으로 비교하며 커스텀 모드는 리더보드를 끈다[S9].
8. **검증은 결정적 엔진 재사용 시뮬레이터 + 봇 등급별 클리어율.** 리플레이 검증 엔진과 같은 코드로 헤드리스 시뮬레이션을 돌려 스테이지마다 "여유도(margin)" 곡선이 톱니 목표 대역 안에 있는지 CI에서 확인한다.

## 1. 웨이브 설계

### 1.1 웨이브 예산(threat budget / point-buy) 방식

- 원리: 각 적 종류에 **단가(cost)** 를 매기고, 웨이브마다 **예산 함수**로 총 위협량을 정한 뒤, 예산 안에서 적 조합을 산다. 오픈소스 웨이브 생성기 td-wavegen이 이 형태(몹 단가 + 웨이브별 예산 함수 → 웨이브 구성)를 그대로 쓴다 [S10]. 학술 쪽은 예산 대신 적합도(fitness: 기지 피해 정도·적 이동 거리)로 진화 알고리즘이 웨이브를 설계한다 [S11], NEAT 신경망 "웨이브 매니저"가 수작업 웨이브와 체감 차이가 없었다는 블라인드 A/B 결과도 있다 [S12].
- 장점: (a) 난이도를 숫자 하나로 조절, (b) 수작업 웨이브와 절차 생성 웨이브를 같은 척도로 비교, (c) 무한 모드·일일 시드에 그대로 확장.
- 단점: 단가가 실제 위협을 잘못 반영하면(예: 공중 적은 대공 타워 없으면 무한대 위협) 예산이 의미를 잃는다 → **단가는 "기준 방어 대비 EHP" 로 산정하고, 공중·면역 같은 상성 적은 "카운터 보유 시 단가"로 매긴 뒤, 도입 스테이지 이전에는 출현 금지**로 다룬다. (제안)

### 1.5 톱니형 곡선 · 플로우

- **톱니형(sawtooth)**: 전체 추세는 오르되 상승 → 정점 → 휴식이 반복되어야 피로가 쌓이지 않는다 [S16][S17]. Left 4 Dead AI Director도 "조용하면 공격을 계획, 격전이 길면 진정시킨다"는 긴장 순환으로 페이싱한다 [S18].
- **새 메커닉 배치 리듬**(Trinity Part 7): `A | B | AB | REST | C | AC | BC | REST | ABC` — 조합 직후, 새 요소 도입 직전에 휴식 [S16]. 웨이브 단위·스테이지 단위 양쪽에 적용한다.
- **플로우**: 도전과 능력의 균형 구간(불안·지루함 회피)에 머물게 한다는 Csikszentmihalyi 이론을 Jenova Chen이 게임 난이도에 적용했다 [S13]. TD에서 "능력" = 플레이어가 그 시점까지 쌓을 수 있는 방어력(경제 × 판단), "도전" = 웨이브 EHP. → **2장 경제 곡선과 1장 예산 곡선의 비율이 곧 플로우 지표**다.

## 2. 경제 곡선

### 2.1 원칙: 수입 vs 필요 DPS

- 필요 DPS(웨이브 n) ≈ `웨이브 총 EHP / 노출시간` (노출시간 = 적이 타워 사거리 안에 머무는 시간, §4.1).
- 공급 DPS ≈ `누적 사용 가능 골드 × 효율 골드당DPS × 배치 효율 η`.
- **여유도(margin) M(n) = 공급 DPS / 필요 DPS**. 톱니의 정점 웨이브에서 M이 최소, 휴식 웨이브에서 회복되게 맞춘다. (제안)
- **구조적 함정**: 예산 B(n)이 n²로 늘면 누적 수입은 ∑B ≈ n³ 로 늘어 M(n)이 후반에 계속 커진다(후반 쉬움, "돈이 남아돈다"는 흔한 플레이어 피드백 [S19]). 대응:
  1. 킬 보상 비율을 웨이브에 따라 감쇠 (BTD6 [S2][S3])
  2. 상위 업그레이드일수록 골드당 DPS 체감(비용 초선형) — Schreiber의 비용 곡선(transitive mechanics: 강할수록 비용이 비선형으로 상승) [S20]
  3. 후반 웨이브에 방어·면역·공중을 섞어 "골드로 산 DPS"의 유효율을 낮춤

### 2.3 난이도별 경제 처리

- BTD6는 난이도를 **타워 비용 배율**로 표현한다: Easy ×0.85, Medium ×1.0, Hard ×1.08, Impoppable ×1.2 (위키 비용표의 비율로 확인) [S4].
- KR은 보상·속도는 그대로 두고 **적 HP만** 바꾼다 [S5].
- 우리: 두 축 모두 permille 정수로 (§5.4). 보상 자체를 바꾸면 "킬 골드 → 다음 웨이브 대비" 피드백 루프가 모드마다 달라져 시뮬레이션 검증 매트릭스가 커지므로 보상은 고정. (제안)

## 3. 스테이지 진행

### 3.1 캠페인 규모·모드 (사례)

- Kingdom Rush: 캠페인 + 3별 후 해금되는 **Heroic Challenge**(목숨 1, 6웨이브, 전용 적·시작 골드) · **Iron Challenge**(적 수 숨김, 타워 제한) — 각 클리어 시 별 1개. 캠페인은 목숨 20, **남은 목숨 18+ → 3별, 6~17 → 2별, 그 외 1별** [S5]. 캠페인 맵 수 **(미확인 — 검색에서 수치 미확보)**.
- BTD6: 난이도(Easy/Medium/Hard/Impoppable) × 모드. **CHIMPS**(Impoppable 클리어 후 해금, Hard 기반 R6~100, 목숨 1, 이어하기·추가 수입·Monkey Knowledge·파워·판매 금지) [S8].
- 데일리: Slay the Spire Daily Climb — **전원 같은 시드**, 무작위 수정자 3개(초기 4개는 너무 어려워 3개로 축소), 리더보드 비교 [S9].

## 4. 밸런싱 방법

### 4.1 EHP · 필요 DPS

- **EHP**(유효 체력): `EHP = HP × 1000 / 피해배율‰`, 피해배율‰ = 방어·속성 상성을 적용한 실제 피해 비율. 예) 물리 방어 50% → 물리 타워 기준 EHP = HP×2. (제안: 퍼센트 방어. 고정 감산 방어는 저데미지 연사 타워를 0으로 만들 수 있어 별도 검토)
- **노출시간** `T = 사거리 안 경로 길이 / 적 속도` (타워 위치별). 둔화는 `T`를 늘리는 효과로 환산.
- **필요 DPS(웨이브)** ≈ `∑EHP / T_eff`, 동시 체류 수가 많을수록(러시) 단일 타워는 불리 → 광역 타워는 `타격 대상 기대 수`를 곱해 DPS를 환산한다.

### 4.2 타워 가성비 지표

| 지표 | 식 | 쓰임 |
|---|---|---|
| 골드당 DPS | `유효 DPS / 누적 비용` | 같은 단계 타워 간 형평. 상위 단계일수록 체감 (§2.1) |
| 유효 DPS | `피해 × 공격속도 × 기대 타격 수 × 상성‰ × 가동률` | 가동률 = 사거리 내 표적 존재 시간 비율 |
| 오버킬 손실 | `낭비 피해 / 총 피해` | 고단일피해 타워의 저HP 러시 대응 실효 |
| 카운터 의존도 | 특정 적 유형 대응 시 대체 불가 여부 | 공중·은신 등 "필수 타워" 표시 |

- 비용 곡선 개념(비용과 이득이 같아야 하거나, 정해진 비율로 비선형 상승)은 Schreiber·Romero의 Game Balance(Transitive Mechanics and Cost Curves)가 표준 참고 [S20].

### 4.3 스프레드시트 모델 → 시뮬레이터

1. **스프레드시트**(1차): 웨이브별 `B(n)`, 총 EHP, 누적 골드, 기준 빌드의 공급 DPS, M(n) 열. 거친 곡선 확인용.
2. **시뮬레이터**(정본): 배치·경로·사거리·타게팅·상태효과가 얽혀 해석식으로는 오차가 크므로, 결정적 엔진을 헤드리스로 돌린다(§6).
3. **자동 밸런싱**: 시뮬레이터 위에서 `B(n)` 계수·`S_s`·적 단가를 탐색(그리드/진화). 학술 사례: GA·EDA로 웨이브 설계 [S11], NEAT 웨이브 매니저 + 타워 배치 커리큘럼 [S12].

### 4.4 플레이테스트 지표 (텔레메트리)

- 스테이지별: 첫 시도 클리어율, 재시도 횟수 분포, 실패 웨이브 히스토그램(특정 웨이브에 몰리면 스파이크 과다), 별 분포, 평균 남은 목숨, 이탈(중도 포기) 지점, 클리어 시간.
- 경제: 웨이브 종료 시 미사용 골드(누적되면 너무 쉬움/선택지 부족), 판매 빈도(높으면 함정 타워 존재).
- 다양성: 클리어 빌드의 타워 구성 엔트로피, 상위 1개 타워 점유율(지배 전략 탐지).
- 랭킹 리플레이를 그대로 분석 데이터로 쓸 수 있다(서버가 이미 명령 로그를 보관) (제안).

### 4.5 동적 난이도 조정(DDA) 장단점

| 장점 | 단점 |
|---|---|
| 개인별 플로우 구간 유지 [S13] | **같은 스테이지 결과가 비교 불가 → 랭킹과 정면 충돌** |
| 초보 이탈 감소 | 들키면 성취감 저하·악용(일부러 못하기) |
| Hamlet(Hunicke): 공급/수요 조절로 난이도 제어 [S14] | 결정적 리플레이 검증에 상태 변수 추가 필요 |

- 결론(제안): **숨은 DDA 미도입.** 대안은 ① 명시 모드 선택, ② 연속 실패 시 "쉬움 전환 제안" UI, ③ 랭킹 미등록 "연습 모드"의 보조 옵션(시작 골드 +, 배속 −).

## 5. 우리 게임 초안 공식 (전부 제안, 정수 연산)

**정수 규약** (제안)
- 배율은 **permille(‰, 1000 = ×1.0)**, 곱 후 **내림**: `mulDiv(x, m) = floor(x × m / 1000)` (KR도 HP 배율 후 내림 [S5]).
- 곱셈 순서를 엔진·서버 공통 상수로 고정(순서가 바뀌면 내림 결과가 달라진다).
- 중간값 상한 검사: JS `Number` 안전 정수(2^53) 이내 — 무한 모드 최대 웨이브에서 `HP × ‰ × ‰` 최대값을 테스트로 고정. 필요하면 `BigInt` 대신 상한 캡.
- 난수는 시드 PRNG 하나(리서치 04 소관). 이 장의 공식은 난수 없이도 결정되며, 웨이브 구성 선택만 PRNG를 쓴다.

### 5.1 웨이브 예산

```
B(n)     = 20 + 8·n + floor(3·n² / 5)                 // 기본 위협 예산 (n = 1..)
SAW      = [1000, 1050, 1250, 700, 1400]               // 5웨이브 주기: 기본·기본+·러시/스파이크·휴식·보스/엘리트
Bw(s,n)  = mulDiv( mulDiv(B(n), SAW[(n-1) % 5]), S_s × D_budget / 1000 )
```

- `S_s`: 스테이지 배율‰ (도입 스테이지 낮게·보스 스테이지 높게, 예: 1스테이지 800 … 12스테이지 1600).
- `D_budget`: 난이도 예산 배율‰(기본 1000, HP는 §5.4가 따로 담당하므로 보통 1000 고정).
- 표(보통, `S_s`=1000):

| n | B(n) | ×SAW → Bw | 역할 |
|---|---|---|---|
| 1 | 28 | 28 | 기본 |
| 3 | 49 | 61 | 러시 |
| 4 | 61 | 42 | 휴식 |
| 5 | 75 | 105 | 보스 |
| 10 | 160 | 224 | 보스 |
| 15 | 275 | 385 | 보스 |
| 20 | 420 | 588 | 보스 |
| 30 | 800 | 1120 | 보스 |

- 구성 알고리즘: 역할별 허용 적 풀에서 (보스 웨이브는 보스 단가 선차감) 남은 예산으로 단가가 맞는 적을 PRNG로 뽑아 0이 될 때까지 구매, 남는 잔액은 가장 싼 적으로 채우거나 버림(규칙 고정).

### 5.2 적 HP · 단가

```
hpMul(n)      = 1000 + 50·(n − 1)                       // ‰, 웨이브당 +5% (선형)
HP_e(n, d)    = mulDiv( mulDiv(baseHP_e, hpMul(n)), D_hp[d] )
cost_e(n)     = max(1, mulDiv(baseCost_e, hpMul(n)))    // 단가도 HP를 따라 오름 → 같은 예산에서 수 → HP로 이동
count ≈ Bw / cost_e(n)
```

- `baseCost_e` ≈ 기준 방어 대비 EHP 비례로 설정(공중·은신은 카운터 보유 시 EHP 기준 + 기믹 할증). 난이도 HP 배율 `D_hp`는 단가에 반영하지 않는다(어려움 = 같은 수, 더 단단함).
- 속도는 웨이브로 키우지 않는다(캠페인). 속도 차이는 적 종류로 표현 — 속도는 노출시간을 직접 줄여 체감 난이도가 비선형으로 튀기 때문 (제안).

### 5.3 보상 곡선

```
killGold_e(n)   = max(1, mulDiv(cost_e(n), K(n)))       // K(n) ‰ = 킬 보상 비율
K(n)            = 400 (n ≤ 15) · 320 (16~25) · 260 (26~)  // 후반 감쇠 (BTD6 감쇠의 구조 차용 [S2][S3])
clearBonus(n)   = 10 + n                                 // BTD6 100+R 구조 [S2]
earlyBonus      = floor(remainTicks × clearBonus(n) / countdownTicks)   // 남은 카운트다운 비례, 최대 clearBonus
sellRefund      = mulDiv(totalSpent, 700)                // 같은 준비 단계 즉시 판매는 1000
interest (선택) = min(cap, floor(min(gold, cap₀) × 20 / 1000))  // 1차 미도입 권장
```

- 웨이브당 수입 ≈ `0.4·Bw + 10 + n` → 수입이 위협에 비례, K(n) 감쇠로 누적 n³ 효과 상쇄.
- 검증 목표: 기준 봇의 M(n)이 톱니 목표 대역(§6.3)에 들도록 `K(n)` 구간값을 튜닝.

### 5.4 난이도 모드

```
D_hp   = { easy: 800, normal: 1000, hard: 1200, impossible: 1200 }
D_cost = { easy: 850, normal: 1000, hard: 1080, impossible: 1200 }   // 타워 구매·업그레이드 비용에 적용
D_spd  = { ..., impossible: 1100 }
lives  = { easy..hard: 20, impossible: 1 }
stars  = lives ≥ 18 → 3 · lives ≥ 6 → 2 · else 1     // KR 기준 [S5], 불가능은 클리어 = 3별
```

### 5.5 무한 모드 배율 (마지막 설계 웨이브 이후 w = 1, 2, …)

```
endlessHp(w)  = 1000 + ∑_{i=1..w} step(i)      // 가산 램프 (BTD6 구조 [S1])
step(i)       = 20 (i ≤ 20) · 50 (21~40) · 150 (41~60) · 350 (61~)
endlessSpd(w) = min(1600, 1000 + 20·w)          // +2%/웨이브, ×1.6 상한 (BTD6 R81~100 +2%, R101 ×1.6 [S1])
endlessK(w)   = 200 (w ≤ 20) · 100 (21~40) · 50 (41~)   // 보상 감쇠
예산          = B(N_last + w) 그대로, 적 HP 에 endlessHp 를 추가 곱
```

- 값: endlessHp(20)=1400, (40)=2400, (60)=5400, (100)=19400, (120)=26400. 웨이브 60 이후 급격한 벽 → 무한 랭킹 점수가 자연히 수렴.
- 누적 합은 닫힌식으로 계산(루프 대신)하거나 웨이브 전환 시 누적값을 상태로 들고 간다 — 둘 다 결정적.

### 5.6 랭킹 점수 초안 (리서치 04와 정합 필요)

```
stageScore = 10000 × stars + 200 × livesLeft + floor(unspentGold / 10) + earlyCallTicksSaved / 30
endlessScore = (도달 웨이브) × 100000 + 그 웨이브 처치 비율‰
```
- 동점 해소용 보조항만 추가하고, 핵심은 별·목숨. 배속(Q3)은 점수에 넣지 않는다 (제안).

## 6. 밸런스 검증 — 지표·시뮬레이터 설계 (제안)

### 6.1 구조

```
[stage JSON + 난이도] → [결정적 엔진(리플레이 검증과 동일 코드)] ← [봇: 명령 로그 생성기]
                                   ↓ 헤드리스 고속 실행 (렌더 없음)

```
- **엔진 공유가 핵심**: 시뮬레이터 결과와 실제 플레이·서버 리플레이 검증이 같은 코드 → "시뮬레이터에선 깨지는데 게임에선 안 깨짐" 불일치 제거.
- 봇은 명령 로그(`place/upgrade/sell/callEarly` + tick)만 내므로, 봇 플레이를 그대로 리플레이 픽스처로 저장 가능.

| Greedy | 매 준비 단계에 "골드당 유효 DPS 최대" 구매(경로 커버리지 가중) | 보통 기준선 |

### 6.3 지표와 목표 대역

| 지표 | 정의 | 목표 (제안) |
|---|---|---|
| 클리어율 | 시드 N개(웨이브 구성 PRNG) 중 클리어 비율 | 보통: Greedy ≥ 95%, Novice 40~70% · 어려움: Greedy 50~80% |
| 여유도 M(n) | 웨이브 n 동안 `1 − (가장 멀리 간 적의 경로 진행률)` 또는 공급/필요 DPS | 톱니 형태: 보스 웨이브 최저, 휴식 웨이브 회복. 단조 증가(후반 쉬움) 금지 |
| 누수 분포 | 웨이브별 잃은 목숨 | 특정 웨이브 집중(스파이크 과다) 경보 |
| 미사용 골드 | 웨이브 종료 시 잔액 / 누적 수입 | 후반 30% 초과 지속 시 경제 과잉 |
| 타워 다양성 | Search 봇 상위 빌드 중 단일 타워 점유율 | 60% 초과 시 지배 전략 의심 |
| 모드 간 폭 | 쉬움/불가능의 Greedy 클리어율 차 | 단조성(쉬움 ≥ 보통 ≥ 어려움) 보장 |
| 결정성 | 같은 시드·로그 2회 실행 결과 해시 | 100% 일치 (테스트) |

### 6.4 운용

- 스테이지 JSON 변경 PR마다 CI에서 `stage × 난이도 × 봇 × 시드 K개` 매트릭스 실행, 목표 대역 이탈 시 실패.
- 자동 튜닝은 오프라인 스크립트로만(계수 제안 → 사람 승인 → JSON 반영). 런타임에서 계수를 바꾸지 않는다(랭킹 비교 보장).

## 7. 메타 진행 · 랭킹 공정성

- 영구 강화가 있으면 같은 스테이지 점수가 "실력 + 누적 플레이량"의 함수가 된다. GMTK는 영구 강화 없는 게임은 실력에 보상하고, 있는 게임은 그라인드로 실력 차를 메울 수 있다고 정리한다 [S21].
- 사례: BTD6 CHIMPS는 Monkey Knowledge·파워·추가 수입을 끈다 [S8]. Slay the Spire는 데일리를 전원 같은 시드로 비교하고, 커스텀 모드는 업적·리더보드를 끈다 [S9].
- 권장(제안, Q4 연결):
  1. **1차는 메타 진행 없음** — 해금은 "스테이지 진행으로 타워/모드가 열리는 것"까지만(능력치 강화 없음).
  2. 도입한다면 **랭킹 모드(스테이지 랭킹·일일·무한)는 메타 효과를 끈 정규화 규칙**으로만 시뮬레이션·검증하고, 캠페인 진행용 별도 모드에서만 적용.
  3. 업적·코스메틱 보상은 난이도에 영향 없음 → 자유롭게.
